## PMS-214 / PMS-274: filtro de incidencias

La fila `SOLUCIONADA` del catálogo V4 se denomina `Solucionada - pendiente de confirmación`. `TodasComponent` comparaba ese nombre completo con el texto `Solucionada` del selector, de modo que excluía el registro correcto. La corrección compara `estadoCodigo` con una clave normalizada y mantiene compatibilidad con respuestas históricas sin código.

Se ejecutó `node scripts/test-filtros-catalogo.cjs` sobre el componente real transpilado, con las signals de Angular y un servicio sustituido por datos sintéticos. La etiqueta larga procede del SQL del proyecto; los IDs y registros de prueba no representan nuevas incidencias reales. Los casos verifican estado + prioridad, ausencia de prioridad, limpieza de controles/listado, EN_ATENCION, exclusión de estados distintos y compatibilidad histórica.

| Versión ejecutada | Aprobados | Fallidos |
| --- | ---: | ---: |
| Componente anterior, archivo extraído de main | 3 | 3 |
| Componente corregido | 6 | 0 |

La comparación se reprodujo con `PMS_FILTER_BASELINE_FILE` apuntando al archivo anterior. El runner ejecuta la lógica real y el inyector de Angular; no renderiza el navegador ni consulta la base de datos. Se incorporan además seis casos Jasmine equivalentes para Karma. TypeScript de los specs y compilación Angular del entorno de validación aprobaron. Karma no pudo abrir su puerto en la sesión restringida. El re-test visual del registro original de PMS-214 sigue pendiente y no debe atribuirse a esta ejecución automática.

## PMS-265 / PMS-267: consulta de alertas por otro residente

Se agregó `AlertaInternaPropiedadTest` con el controlador y servicio reales, Spring MockMvc y repositorios Mockito. Dos perfiles residentes sintéticos se autentican en el SecurityContext de prueba.

| Caso | Resultado esperado | Resultado observado |
| --- | --- | --- |
| Autor consulta `/api/alerta-interna/77` | HTTP 200 | HTTP 200 |
| Segundo residente consulta el mismo ID | HTTP 403, sin contenido de la alerta | HTTP 403, cuerpo vacío |
| Segundo residente consulta `mis-alertas` sin registros propios | HTTP 200 y lista vacía | HTTP 200 y `[]` |

Tres pruebas aprobadas. El endpoint y la lógica de propiedad se ejecutaron sin servidor de red; las identidades y repositorios son dobles de prueba. No se utilizaron cuentas, tokens ni registros reales de Firebase/MySQL. La ejecución se hizo directamente con JUnit y bibliotecas locales disponibles, no mediante una ejecución completa de Maven con todas las versiones del POM. La ejecución normal es `mvn -Dtest=AlertaInternaPropiedadTest test`.
